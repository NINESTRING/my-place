# 카테고리 공유 링크 — 설계

2026-08-24

## 목적

사용자가 자기 카테고리를 골라 공유를 켜면 추측 불가능한 URL이 만들어지고,
그 링크를 받은 사람은 **로그인 없이** 그 카테고리에 속한 장소들을 지금의
지도 화면(읽기 전용)으로 볼 수 있다.

예: "미사" 카테고리를 공유로 바꾸고 링크를 친구에게 보내면, 친구는
`/share/<token>` 으로 접속해 미사 장소들을 지도와 목록으로 본다.

## 결정 사항

| 결정 | 선택 |
| --- | --- |
| 공유 화면 | 지금의 `/` 지도 화면과 동일한 UI의 읽기 전용 모드 |
| URL 형태 | 추측 불가 토큰 (`/share/x7Kp9mQ2…`) |
| 끄기/켜기 | 토큰 영구 보관 — 다시 켜면 같은 링크가 살아난다 |
| 공유 UI 위치 | 카테고리 관리 화면(`CategoryManager`, 등록·수정 폼 안의 `관리` 토글) |
| 데이터 로드 | 서버에서 카테고리의 모든 장소를 한 번에 조회, bounds 재조회 없음 |

접근 방식 대안 중 "공유 전용 bounds API"(장소 수천 개 대응)와 "별도 경량
뷰어 컴포넌트"(중복 큼)는 기각했다. 한 카테고리의 장소는 많아야 수십~수백
개라 한 번에 내려도 부담이 없고, 필요해지면 그때 bounds API 를 추가한다.

## 1. 데이터 모델

`Category` 에 컬럼 두 개를 추가한다:

```prisma
model Category {
  // ...기존 필드...
  shareToken   String?  @unique @map("share_token")   // 첫 공유 시 생성, 영구 보관
  shareEnabled Boolean  @default(false) @map("share_enabled")
}
```

- **`shareToken`** — 처음 공유를 켤 때 `crypto.randomBytes(16)` 을
  base64url 로 인코딩(22자)해 생성한다. 새 의존성 없음. 공유를 꺼도 지우지
  않아 다시 켜면 같은 링크가 유효해진다.
- **`shareEnabled`** — 링크 유효 여부는 이 플래그 하나로 판단한다. 토큰이
  있어도 `false` 면 404.
- 기존 행은 기본값(null / false)이라 데이터 마이그레이션 불필요.
  `prisma db push` 로 충분하다.

## 2. 라우트와 보안

새 페이지 **`app/share/[token]/page.tsx`** (서버 컴포넌트, `force-dynamic`):

- 토큰으로 카테고리를 조회하고 `shareEnabled` 가 아니면 **`notFound()`** —
  존재하지 않는 토큰과 꺼진 토큰이 같은 404를 받아 존재 여부가 새지 않는다
  (기존 수정·삭제 경로와 같은 원칙).
- 유효하면 그 카테고리의 **모든 장소를 서버에서 한 번에 조회**한다. 조회
  함수는 `places.server.ts` 의 `getSharedPlaces(token)` — 기존 함수들처럼
  스코프(여기서는 토큰)가 필수 인자다.
- 초기 지도 범위는 장소 전체를 덮는 bounding box 를 순수 함수
  (`lib/places.ts`)로 계산한다. 장소가 0개면 기존 `FALLBACK_BOUNDS` 와 같은
  기본 범위.
- **다른 카테고리 이름은 내리지 않는다.** 공유된 장소가 개인적인 다른
  카테고리도 갖고 있을 수 있으므로, 공유 화면에서는 카드의 카테고리 줄
  자체를 숨긴다(전부 같은 카테고리라 정보 가치도 없다).
- 공유 페이지에 `robots: noindex` 메타를 넣는다 — 링크를 아는 사람만 보는
  페이지라는 의도와 일치시킨다.
- 공개되는 정보: 카테고리 이름, 각 장소의 제목·설명·사진·좌표·촬영일.
  사진은 이미 public 버킷이라 새로 열리는 것은 없다.

## 3. 공유 토글 UI와 서버 액션

**서버 액션** — `src/actions/category.ts` 에
`setCategorySharingAction({ id, enabled })` 하나를 추가한다:

- 세션이 없으면 거부. 소유자 검증은 기존 수정·삭제와 같은 원칙으로
  `where: { id, userId }` 를 SQL 한 문장에 넣는다.
- 켤 때 토큰이 없으면 그때 생성해 저장한다. 유니크 충돌 시 재시도.
- 성공 시 갱신된 카테고리(공유 상태 + 토큰)를 돌려준다.

**타입** — `CategorySummary` 에 `shareEnabled`, `shareToken` 을 추가한다.
이 타입은 본인 세션에서만 조회되므로 자기 토큰이 폼에 내려오는 것은 문제가
없다. 공유 URL 은 클라이언트에서 `${location.origin}/share/${token}` 으로
조립한다.

**UI** — `CategoryManager` 의 각 행(이름변경·삭제 버튼 옆)에:

- **공유 토글 버튼**(Share2 아이콘): 누르면 켜기/끄기. 켜져 있으면 아이콘을
  강조색으로 표시.
- 켜진 행에만 **링크 복사 버튼**: `navigator.clipboard.writeText` 후
  "공유 링크를 복사했습니다" 토스트. 처음 켜는 순간에도 곧바로 복사할 수
  있게 켜기 성공 토스트에서 링크 복사를 함께 안내한다.
- 카테고리 **삭제 시 공유 링크도 함께 사라진다**는 안내를 삭제 확인 문구에
  한 줄 추가한다.

## 4. 읽기 전용 화면

`PlaceExplorer` 에 `share` 모드(prop)를 추가해 `/share/[token]` 이 재사용한다:

- **숨김**: 등록 버튼, 로그인/로그아웃 버튼, 카드의 `⋮` 수정·삭제 메뉴,
  카테고리 필터 칩, `전체/지도 영역` 범위 토글(공유 화면은 항상 전체).
- **비활성**: 팬/줌 시 `/api/places` 재조회(받은 장소가 전부), 지도 위치
  localStorage 저장(방문자 브라우저에 상태를 남기지 않고, 주인이 자기 지도
  위치를 덮어쓰는 사고도 막는다).
- **추가**: 화면 상단에 공유 헤더 한 줄 — 카테고리 이름과 "○○개의 장소".
  방문자가 무슨 화면인지 알 수 있는 유일한 단서다.
- 목록 패널·마커 팝업·flyTo 는 그대로 동작한다.

## 5. 테스트

기존 패턴대로 순수 함수만 Vitest 단위 테스트:

- 토큰 생성 함수 — 길이, URL-safe 문자만 포함, 호출마다 다른 값.
- bounding box 계산 — 일반 케이스, 장소 1개, 0개(fallback).
- `setCategorySharingAction` 입력 Zod 스키마 — id 양의 정수, enabled 불리언.

공유 페이지 자체(404 분기, 읽기 전용 렌더)는 기존 관례대로 수동 확인에
의존한다(컴포넌트/E2E 테스트 부재는 README 의 알려진 이슈).

## 에러 처리

- 잘못된/꺼진/삭제된 토큰 → 404 (`not-found.tsx` 재사용).
- 클립보드 API 실패(비보안 컨텍스트 등) → 에러 토스트로 안내.
- 공유 토글 액션 실패 → 기존 카테고리 액션들과 같은 `{ ok: false, error }`
  → 에러 토스트.
